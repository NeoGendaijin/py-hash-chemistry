# Proposed Correction to the ALIFE 2026 Paper

Paper: Ilya Horiguchi and Hiroki Sayama, "Space-Size-Driven Transition of Evolutionary Dynamics in Structural Cellular Hash Chemistry", ALIFE 2026 Proceedings, doi:10.1162/isal.a.976.

After publication we found that the simulator used for this paper differed from its rule description. We correct that description below. The published data, figures and tables were produced by the earlier implementation and are not replaced by results from a different model.

## Winner selection

Methods step 5 and Algorithm 1 should specify the following rule. If the component of the first sampled cell has the higher score, it wins. If the component of the second sampled cell has the higher score, it wins with probability one half. Exact ties are broken uniformly at random. Because the two active cells are sampled independently with exchangeable order, the higher-scoring component wins three quarters of non-tied contests. The earlier statement of deterministic higher-score selection was incorrect. The cause was padding in a fixed-length array used for winner selection in JAX.

The implementation therefore differs from the original Mathematica SCHC in both the surrogate score and the strength of selection. The original implementation always selects the higher score outside ties. References to preserving its competition rule should be read with this correction.

## XOR score

The implemented XOR formula is unchanged. Its interpretation requires qualification: aggregation by XOR makes the score depend on three aggregates of cell types and position terms. Permuting cell types within a fixed shape does not change the score, and that shape permits at most 1,024 distinct scores for types 1-1,000. The score is reproducible and varies with these aggregates; it is not a separate pseudo-random assignment to every distinct typed pattern.

## Corner write and measured novelty

The padded JAX scatter redirects invalid writes to cell (0,0), which can suppress a valid update to that cell. Published runs retain this implementation behavior. It is preserved in the archived code and can be selected explicitly in the revised code with legacy_corner=True; ordinary revised JAX execution drops invalid scatter entries instead.

References to the cumulative number of distinct replicated patterns should read "the cumulative number of distinct component patterns observed in sampled configurations". The measurement includes components present at observation times, not exclusively successful replication events.

The statement that size-score correlations above the reported transition are all below -0.75 should read "negative, reaching -0.56 at L=380 (Table 2)". This makes the text consistent with the published table.

## Scope and subsequent re-examination

The published results describe the implemented stochastic-selection/XOR-score variant. They do not establish the same threshold for deterministic-selection SCHC. In a revised companion manuscript under consideration at npj Complexity, we recomputed the size scan using deterministic higher-score selection and a nonlinear per-cell surrogate score, with 100 runs at each of 19 sizes. Runaway remains stochastic but its probability rises most steeply near L=220-240 within 20,000 steps; the former L=300-320 threshold is not retained. These are new results for corrected rules, not replacements for the data generated by the earlier variant.

At L=100 and 2,000 steps, comparisons with the original Mathematica data found differences in 23 of 35 measure-by-window comparisons for the earlier simulator (16 after Holm correction), versus none for corrected winner selection with the replacement score (smallest unadjusted p=0.06). This finite validation does not establish equivalence between implementations or across spatial sizes.

## Code

The implementation that generated the published results remains at tag alife2026-camera-ready of https://github.com/NeoGendaijin/py-hash-chemistry. Its behavior can also be selected in the revised JAX implementation with winner_rule="legacy", score="xor", legacy_corner=True. The revision code/data package is designated npj-complexity-rev1 and documents the corrected and earlier modes separately.

We apologize for the errors in the model description.
